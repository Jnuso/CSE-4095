# Existing behavior contracts

Read the relevant entries when changing settings, storage, practice review or statistics. These preserve accepted decisions; they do not authorize future phases. Historical evidence remains in DEVELOPMENT_LOG.md.

- Accepted Phase 10 defaults: count every reported answer including incomplete sessions; label incomplete recent sessions; statistics reset preserves preferences; initially show 10 recent sessions with Show more. These decisions do not authorize implementing Phase 10 until requested.

- Phase 11 defaults are saved explicitly through Settings; individual session setup overrides must not rewrite them. Sound defaults off; animation and explanations default on. Keep browser audio failures from interrupting practice.

- Clear All Application Data requires explicit destructive confirmation and restores preferences as well as history. It may deliberately replace protected app data, but must touch only the app's storage key, preserve unrelated data, report write failures honestly, and prevent stale tabs restoring erased records/pending preferences.

- Phase 12 mistake counts follow self-reported wrong answers, keyed by operation, ordered operands and difficulty. Capture events before trimming session details; preserve idempotence across snapshots, retries and tabs. History reset and Clear All erase both the journal and cached patterns. Use the later phase rules below for review/mastery gains.

- Phase 14 review filters source patterns by selected operation/difficulty, while valid inverse questions may use a related operation. Self-report is authoritative; consecutive successes use settings.masteryThreshold (default 3). Wrong review updates the original pattern, resets progress, and does not create a duplicate generated-fact pattern.

- Keep reviewEvents as authoritative deduplicated right/wrong evidence alongside base mistakeEvents. Capture before session trimming, merge both with reset protection, replay chronologically and do not restore mastery from cache when a present journal has no supporting evidence. A later regular miss reopens the original. The displayed card may finish after a cross-tab update; subsequent selection uses current progress and excludes mastered patterns.

- Phase 15 Statistics is read-only: mistake/review metrics use all remembered patterns plus deduplicated journal and retained legacy source-review attempts, while the original history totals keep the newest-100-session scope. Attribute wrong inverse reviews to their original fact/operation, include active and mastered patterns in frequency rankings, show all top ties and keep detail sorting deterministic. Browsing views/pagination must not save or change mastery.

- Phase 19 recognizes supported saves and repairs affected categories independently: validate and deduplicate recoverable answers, rebuild session totals, preserve valid preferences and independent mistake/review evidence, and never rewrite merely on read. Unreadable JSON and unsupported versions remain protected. Displayed questions must have four valid choices and match configuration; bounded deterministic fallbacks retain the original review pattern. Page errors preserve layout navigation and provide focused, plain-language recovery without rendering exception details.


- Phase 18 recovery uses the app key in per-tab sessionStorage. A versioned snapshot retains the exact current question/choices, selected/revealed card, attempts, review identity and session configuration. Recovery is tied to its history entry, validates before use and is fenced by durable reset markers/completed records. Finishing or intentionally leaving erases question state and closes that entry. Invalid/closed recovery routes to safe setup. Ordinary localStorage history remains durable; per-tab recovery is not a promise of recovery after a tab/browser is closed.
- Router-managed active-session navigation uses React Router data-router blockers with accessible Keep practicing / End session and leave choices, including Back/Forward. Reported answers are finalized before intentional leave; the unreported card does not count. Reload/tab-close protection uses the browser's native beforeunload support and does not substitute for persisted recovery. Browser restrictions can suppress native prompts. Reset/Clear All also remove this tab's recovery key; other tabs remove it when observing the reset. If removal is unavailable, a visible warning and durable reset fences prevent recovery of erased progress.
- Large saves use lossless on-disk version 2 with journalFormat tuple-v1 above 512 Ki UTF-16 code units when smaller than plain JSON; small saves remain version 1. The in-memory domain model stays version 1. Every original journal/pattern field is preserved, including optional target identity, timestamps and legacy cached progress. Known tuples are expanded and validated using the existing category-repair rules. Unknown versions/encodings stay protected; merely reading never rewrites. Older clients protect version-2 saves rather than overwriting them. Detailed session retention and newest-100 overall statistics are unchanged; compaction is not an unlimited-storage guarantee.
- Privacy preparation: application code asks for no identity/contact fields and contains no analytics, advertising or practice-result uploads. Practice results/preferences stay in browser storage; normal static hosting requests still occur. Settings explains data clearing and same-tab recovery. Manual accessibility/device checks and the final full gate remain separate from this implementation sign-off.

- Professor alignment (2026-10-21): expose the existing masteryThreshold as an explicitly saved integer setting from1 to100, default3; use existing journal replay when threshold changes. Keep current practice defaults, explicit Save, review filters and nonnegative arithmetic. Standalone End Session uses a focus-trapped custom dialog with Keep practicing initially focused, Escape/cancel preserving the exact card, and confirmation excluding the unreported question. Recaps show practice mode and configured session length.

- Statistics navigation (2026-10-21): a labelled section menu provides immediate in-page jumps without changing the route hash or saved data. Desktop navigation stays in the left column; at 900px and below it becomes a two-column menu above content. The current item uses aria-current=location plus bold, underline, background and a left border. Jumps focus the target heading; manual scrolling tracks the current section. These are presentation changes only; statistics calculations and reset behavior are unchanged.
