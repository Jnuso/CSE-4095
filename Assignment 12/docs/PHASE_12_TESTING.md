# Phase 12: Mistake tracking review guide

Live app: https://jnuso.github.io/CSE-4095/

This phase adds saved tracking behind the existing practice screens. Similar-question generation, the Practice Mistakes mode, mastery gains, and detailed mistake dashboards are later phases. Marking a regular answer right does not yet add similar-review progress.

1. **Practice normally:** In a private window, choose five questions. Mark three right and two wrong, regardless of whether the selected choice is mathematically correct. Expect a recap of 5 attempted, 3 right, 2 wrong, and 60%. The two reported misses should be remembered immediately, even before finishing a session.
2. **Refresh and continue:** Refresh the recap, visit Settings and save a preference, then return to Statistics. Counts should not change simply because a page loads or settings save. Use Practice Again for another session; the existing card, keyboard, sound, explanation and animation behavior should still work.
3. **Optional exact saved-data inspection:** In Chrome or Edge, open developer tools, choose Application, then Local Storage for https://jnuso.github.io, and inspect mathPractice.data. Do not edit or delete it. Expand mistakePatterns: each fact contains operation, firstOperand, secondOperand, correctAnswer, difficulty, incorrectCount, similarCorrectCount (initially 0), lastIncorrectAt and mastered (initially false). Two misses on the same operation/ordered operands/difficulty share one pattern with incorrectCount 2; different facts have separate entries. mistakeEvents is the deduplicated evidence used to avoid counting reloads/retries as new misses. These fields are not a new screen in the app yet.
4. **Reset cancellation:** Open Statistics, select Reset Statistics, then Keep my history or Escape. History and remembered mistakes should remain. The reset description now explicitly includes remembered mistakes.
5. **Confirm reset only in a browser where you want to erase this data:** Erase history should clear attempts, sessions, statistics and remembered mistakes while keeping saved preferences. Refresh and inspect again if desired. Start a fresh session afterward; old open sessions cannot restore erased mistakes.
6. **Clear all:** In Settings, cancelling Clear All Application Data must keep everything. Confirming should also erase remembered mistakes, restore original preferences and return Home. A private window avoids clearing your usual saved progress.

Facts distinguish operand order and difficulty. Reversed addition/multiplication facts can become related questions in the following phase, but are separate recorded patterns now. Another reported miss increases the count, updates the latest incorrect date, and resets any existing review progress/mastered flag. Incorrect facts remain remembered after the newest-100-session detail limit; older mistakes deleted before this phase cannot be recovered. The supporting journal grows with missed reports and is subject to browser storage limits. Save failures show the existing warning and retain current in-memory tracking rather than claiming a successful write.

Most new behavior is storage logic, so the automated suite provides the exact checks: repeated misses, report/question deduplication, out-of-order dates, malformed entries, legacy-history backfill, 101-session retention, delayed snapshots, write failure/retry, two tabs, reset protection and real browser restart. Browser checks also scan the recovery warning with the existing accessibility rules. Tests use disposable contexts and never alter your normal browser profile.

From math-practice-app, run `npm.cmd run check:all`. TESTING.md describes reports; DEVELOPMENT_LOG.md records actual completed verification, review and deployment results. The TODO is updated only after the full gate passes.
