## Pages-specific build

The normal local build uses BrowserRouter and dist/. The dedicated Pages command is:

```powershell
npm.cmd run build:pages
```

It builds with mode pages, relative assets, and separate dist-pages output. The committed `.env.pages` contains only `VITE_ROUTER_MODE=hash`, not credentials. HashRouter produces routes such as `https://jnuso.github.io/CSE-4095/#/practice/setup`. The fragment is handled in the browser, so refreshing a deep link requests the same static entry page instead of requiring a server rewrite. Use the hash-style links generated by the app.

The skip link focuses main content without replacing the route fragment. It also scrolls main content into view in real browsers. The saved-data format is unchanged.

## Verify locally

From math-practice-app:

```powershell
npm.cmd run check:all
```

This includes the normal regression/accessibility suite plus `test:pages`, which rebuilds the Pages variant and runs desktop/mobile tests against a strict static server under /CSE-4095/ at port 4373. The server has no SPA fallback and serves only dist-pages. Tests cover hash routes and refreshes, absent-session redirects, unknown routes, skip-link focus, full session/summary persistence, history navigation, and an axe summary scan. Incorrect non-hash route URLs intentionally return 404. Browser data is isolated from the student's hosted/local profiles.

Focused commands:

```powershell
npm.cmd run test:pages
node scripts/browser-tests.mjs show-report output/playwright/pages-report
```

Normal reports remain in regression-report; Pages reports/results are separate and ignored. These are Chromium desktop/mobile-size checks, not a cross-browser certification.

## Student review after deployment

1. Open the stable address and select Start Practice. Choose 5 questions and complete them, marking three right and two wrong. The recap should show 5 attempts, 3 right, 2 wrong, and 60% accuracy.
2. Refresh the recap. Its saved results should remain. Open setup via `#/practice/setup`, refresh, and confirm the page still loads without a hosting 404.
3. Navigate through Home, Statistics, and Settings. Statistics shows saved progress; Settings saves preferences and offers explicit-confirmation clearing. Use browser Back to check navigation.
4. On setup, focus Skip to content with Tab and activate it. Focus should move to main content while the setup route remains intact.
5. Try the URL on your phone and check that controls fit and can be tapped. Phone and computer histories are independent.

Hosted localStorage belongs to the hosted browser origin. Existing localhost progress is not automatically transferred, and sharing the URL does not synchronize progress across browsers/devices. Refreshing an active question still starts a new session as documented in Phase 9; completed reported attempts remain saved. The later session-recovery phase will address resuming the current question.
