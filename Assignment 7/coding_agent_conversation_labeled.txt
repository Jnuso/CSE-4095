===== YOU =====
Explain how ipynb files work

===== CODING AGENT =====
An `.ipynb` file is a **Jupyter notebook**: a document made of cells you can run one at a time.

- **Code cells** run Python. In your notebook, one cell reads the CSV into a Pandas DataFrame named `df`, then `df.head()` displays its first five rows.
- **Markdown cells** hold headings, explanations, and notes.
- **Outputs** appear below code cells. The notebook can save those outputs, so you may see a table before running anything yourself.

The code runs in a **kernel**, which remembers variables such as `df` while it’s active. Cell order matters: run the cell that creates `df` before any later cell that uses it. If you restart the kernel, run the cells again from the top.

You can open your [notebook](<./Assignment 7/student_habits_analysis.ipynb>) in Jupyter or VS Code and use **Run All** to execute it in order.

===== YOU =====
Explain how the file type works itself

===== CODING AGENT =====
An `.ipynb` file is **a JSON text file with a specific structure**. It stores an ordered list of cells. Each cell records its type (`code` or `markdown`) and its source text. Code cells can also store an execution number and output, such as a displayed table.

A Jupyter-compatible app reads that JSON and presents it as an interactive notebook. When you run a cell, the app sends its code to a Python kernel, then writes the resulting output back into the `.ipynb` file when you save.

The file **does not contain Python itself or your CSV data**. Your notebook stores the instruction to read `class1_student_habits.csv`; it needs that separate file available when the code runs. Saved output may still be visible even if the code has not been run again since the data changed.

===== YOU =====
Is each python cell its own unique python file?

===== CODING AGENT =====
No. The code for every Python cell is stored **inside the same `.ipynb` file** as text in the notebook’s JSON structure. Each cell has its own entry, but it is not a separate `.py` file.

When you run a cell, Jupyter sends its code to the same Python kernel used by the other cells. That is why a later cell can use `df` created in an earlier cell.

===== YOU =====
So how does that work is it essentially just one python file

===== CODING AGENT =====
It **behaves a bit like one Python file** because the code cells share the same running Python session. A variable created in one cell is available to the next:

```python
# Cell 1
x = 5

# Cell 2
print(x)  # 5
```

The difference is that each cell is sent to Python **separately when you run it**. You can run, skip, or rerun cells in any order. So what works depends on the order you *ran* them, which may differ from their order on the page.

The `.ipynb` file stores those separate code snippets, plus notes and saved outputs, rather than being a single `.py` script.

===== CODING AGENT =====
**Grouping** means dividing rows into categories, then calculating a summary for each category.

For example, we could group students by `study_group` (`Yes` or `No`) and calculate the average `exam_score` for each group. Instead of one row per student, the result would have one row per group:

| Study group | Number of students | Average exam score |
|---|---:|---:|
| Yes | … | … |
| No | … | … |

In Pandas, this is called **group by**: choose the column that defines the groups, then choose what to calculate within each group. Common calculations include a count, mean, median, minimum, and maximum.

It differs from **filtering**. Filtering keeps individual students who meet a condition; grouping summarizes all students in each category. When comparing groups, it’s useful to show the **number of students** alongside an average—especially if the groups have different sizes. A difference between group averages also doesn’t, by itself, show that belonging to a study group caused the difference.

**Matplotlib** is a Python library for turning data into charts. Pandas helps us select or summarize the data; Matplotlib draws the result. Its basic structure is a **Figure** (the whole image) containing an **Axes** (the area where one chart is drawn). Despite its name, one `Axes` can be one chart. A typical workflow is: choose the data, create a Figure and Axes, draw the chart, add a title and axis labels, then display it. You’ll often see `matplotlib.pyplot` imported as `plt`; it provides convenient functions for creating and showing figures. In a Jupyter notebook, the chart appears beneath the cell when you run it. [Matplotlib quick start](https://matplotlib.org/stable/users/explain/quick_start.html)
