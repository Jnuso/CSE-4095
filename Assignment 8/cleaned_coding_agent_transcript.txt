Here’s the code for your review. I haven’t added it to the notebook.

from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

numeric_features = [
    "study_hours_per_week",
    "sleep_hours_per_night",
    "attendance_rate",
    "practice_problems_per_week",
    "commute_minutes",
]

numeric_pipeline = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])

Learn the medians, means, and standard deviations from training data.
X_train_numeric = numeric_pipeline.fit_transform(X_train[numeric_features])

Apply those same learned values to the test data.
X_test_numeric = numeric_pipeline.transform(X_test[numeric_features])

print("Training numeric shape:", X_train_numeric.shape)  # (200, 5)
print("Test numeric shape:", X_test_numeric.shape)        # (50, 5)

The distinction between fit_transform on training data and transform on test data is crucial. fit learns the medians and scaling values; transform applies them. We must not fit again on the test set, because that would let test data influence the preparation. The resulting arrays are only the numerical portion; we’ll combine them with the categorical features later.

The correction is that StandardScaler does not put values between 0 and 1. It changes each numerical column so its *training values* have a mean near 0 and a standard deviation near 1:

standardized value = (original value − training mean) ÷ training standard deviation

For example, if average study time were 7 hours with a standard deviation of 2 hours:

- 7 hours → 0 (at the average)
- 9 hours → +1 (one standard deviation above)
- 5 hours → −1 (one standard deviation below)

Values can be negative or greater than 1. Putting values into a 0-to-1 range is a different method, usually called min-max scaling. Standardization makes the *units* more comparable; it does not guarantee that every feature will have equal importance to the model. Scikit-learn’s StandardScaler documentation

preprocessor = ColumnTransformer(transformers=[
    ("numeric", numeric_pipeline, numeric_features),

Important

------------------------------------------------------------------------

CODING AGENT:
Part 6 explains why the scaling step we already added matters. Our numerical inputs use different units: study hours might be around 7, attendance around 85, and commute around 25 minutes. StandardScaler puts each numerical column on a comparable scale using:

\[
z=\frac{x-\mu_{\text{train}}}{\sigma_{\text{train}}}
\]

Here, \(x\) is a value, \(\mu_{\text{train}}\) is that column’s training-data mean, and \(\sigma_{\text{train}}\) is its training-data standard deviation. For a simple example, if training study hours averaged 7 with a standard deviation of 2, then 9 hours becomes \(+1\), 7 becomes 0, and 5 becomes \(-1\). The values are not confined to 0–1.

The scaled training column has a mean near 0 and a standard deviation near 1. The test column may not: we apply the *training* mean and standard deviation to it rather than calculating new ones. This helps models such as Logistic Regression work with features in different units, but it does not force every feature to be equally useful.

I checked our saved pipeline; no change is needed. It fills missing numerical values first, then runs StandardScaler. The combined preprocessor uses fit_transform(X_train) to learn the fill and scaling values, followed by transform(X_test) to apply those same values. Our earlier numerical-only cell does the same thing as a demonstration; it repeats some work when the combined pipeline runs, but it does not use test data to fit the scaler.

1. Why might scaling be useful for Logistic Regression?
   Our numerical features use different units and ranges. Scaling puts them on comparable scales, which helps Logistic Regression learn efficiently. It also means the model’s regularization does not treat a feature differently simply because it is measured in larger numbers, such as minutes rather than hours. Scaling does not make every feature equally important.

2. Does standardization put all values between 0 and 1?
   No. Standardization measures how far a value is from its training mean in standard deviations. Values below the mean can be negative, and values well above it can be greater than 1. A 0-to-1 range is a different scaling method.

   The test set is meant to represent students the model has not seen. CODING AGENT:
Part 9 checks how well our model predicts the 50 test students. We’ll compare its predictions with the actual labels using four measures, because a single score can hide important mistakes.

1. Accuracy is the proportion of *all* test students classified correctly. If 40 of 50 predictions were correct, accuracy would be 80%. That is an example, not our model’s result.

2. The confusion matrix counts correct predictions and both kinds of mistakes:

   | Actual class | Predicted no | Predicted yes |
   |---|---|---|
   | no | Correctly predicted no | Incorrectly predicted yes |
   | yes | Missed a high-scoring student | Correctly predicted yes |

   These cells are often called true negatives, false positives, false negatives, and true positives, respectively. Here, “positive” simply means the yes class.

3. Precision for Yes asks: *Of the students we predicted would score at least 80, how many actually did?*

   \[
   \text{Precision}=\frac{\text{correct yes predictions}}{\text{all yes predictions}}
   \]

   High precision means relatively few students are incorrectly labeled “yes.”

4. Recall for Yes asks: *Of all students who actually scored at least 80, how many did we identify?*

   \[
   \text{Recall}=\frac{\text{correct yes predictions}}{\text{all actual yes students}}
   \]

   High recall means we miss relatively few high-scoring students.

Precision and recall use different denominators. Precision starts with the students the model *predicted* were yes; recall starts with the students who *actually* were yes.

Finally, we’ll compare Logistic Regression’s accuracy with the 60% baseline from Part 4. That baseline predicted “no” for everyone and missed every actual “yes” student. We’ll check whether Logistic Regression improves accuracy and how successfully it identifies “yes” students. Since the test set contains 50 students, each correct prediction changes accuracy by 2 percentage points.

CODING AGENT:
Machine learning is broader than linear algebra, but linear algebra is one of its main tools. Logistic Regression, random forests, and large language models are all forms of machine learning. They differ in what they learn and how they make predictions.

Machine learning means using examples to learn a prediction rule. In our assignment, we chose the features and the model type, but we did not manually decide how much weight to give attendance or study hours. Training finds those details from the 200 students. The test set checks whether the learned rule works on students it did not train on.

Matrices connect directly to our assignment. A matrix is a rectangular arrangement of numbers. After preprocessing, our training data is a 200 × 10 matrix:

- Each row represents one student.
- Each column represents a prepared feature.
- The seven original features became ten numerical columns because one-hot encoding added category indicators.

For Logistic Regression, each feature has a learned weight. For one student, the model calculates:

\[
\text{score}=b+w_1x_1+w_2x_2+\cdots+w_{10}x_{10}
\]

Here, the \(x\) values describe the student, the \(w\) values are learned weights, and \(b\) is a starting offset called the intercept. Matrix multiplication calculates these weighted sums for many students at once. The model then passes each score through a function that converts it into a probability between 0 and 1.

Linear algebra handles those calculations. Probability and statistics help define and evaluate predictions. Calculus and optimization help find weights that reduce prediction error. That is why machine learning draws on several areas of mathematics.

A random forest learns a different kind of rule. It builds many decision trees. A tree is a sequence of questions, with branches depending on the answers. An illustrative tree might ask:

Study hours above 8?
    ├─ Yes → Attendance above 90%?
    └─ No  → Practice problems above 25?

The questions and thresholds are learned from data. In a typical random forest, each tree gets a randomly resampled set of training rows and considers a random selection of features at each split. The forest combines the trees’ predictions; scikit-learn averages their class probabilities. This often produces more stable predictions than one tree. The randomness helps create varied trees—it does not mean the forest guesses randomly. Scikit-learn’s random forest explanation

A forest still receives a data matrix, but its central operation is following branches, whereas Logistic Regression relies on weighted sums.

A large language model is a much larger neural network trained to work with language. Most modern conversational LLMs use a structure called a transformer. At a broad level:

1. Text is divided into tokens—pieces such as words, word fragments, or punctuation.
2. Tokens become vectors, which are lists of numbers.
3. Transformer layers repeatedly transform those vectors. An attention mechanism lets each position draw information from relevant positions in the available context.
4. The network produces probabilities for possible next tokens.

Those layers use substantial matrix arithmetic together with nonlinear functions, allowing much more complex relationships than a single weighted sum. The original transformer paper

During a common form of LLM training, the model sees some text and tries to predict the next token. Its prediction is compared with the token that actually follows, and its weights are adjusted to reduce the error. Repeating this across extensive text helps it learn patterns involving language, facts, code, and tasks. During generation, it selects a next token, adds it to the context, and repeats. Language Models Are Few-Shot Learners

Conversational models often receive further training using examples of helpful responses and feedback about response quality. That helps turn a language model into an assistant that follows instructions. Training language models to follow instructions with human feedback

The overlap looks like this:

| Model | What training learns | How it produces an answer |
|---|---|---|
| Logistic Regression | Feature weights and an intercept | Weighted sum converted to class probabilities |
| Random forest | Branch questions, thresholds, and outcomes in many trees | Combines predictions from the trees |
| LLM | Weights throughout a large neural network | Processes context and generates tokens |

All three learn patterns from examples, can make mistakes, and need evaluation on data outside their training examples. Training and using a model are separate activities: our predictions do not retrain Logistic Regression, and a typical LLM conversation changes the context it reads without updating its underlying weights.

Our legitimate model uses student habits to predict whether an exam score will be at least 80. It achieved 84% test accuracy. The new experiment adds exam_score itself to the inputs, even though we created the target directly from that score:

This connects directly to the matrix and weights explanation. Our legitimate model receives 10 prepared numerical columns. Adding exam score as another numerical feature gives it 11 columns. Logistic Regression can learn a weight for exam score that helps separate the two classes around the 80-point boundary.

Its accuracy will probably rise substantially, although we should calculate the result rather than assume it will be exactly 100%. That improvement would come from supplying information that directly reveals the target.

A proper train/test split does not fix this problem. Every test student would also have their actual exam score included in the inputs. Fitting StandardScaler on training data only is still correct, but scaling does not remove the relationship between exam score and the target.

The same problem could affect a random forest: a tree could learn a question resembling “Is exam score at least 80?” The choice of algorithm does not make those inputs appropriate for predicting an outcome before it is known.

For this experiment, we’ll build a separate Logistic Regression pipeline, add exam score to its numerical features, and evaluate it on the same test students. Comparing it with the legitimate model will show why high accuracy needs to be interpreted alongside what information the model received.
